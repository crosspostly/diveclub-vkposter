# VK Клипы (Clips): почему не через API и как автоматизировать через Playwright

## Наблюдение (проверено живыми тестами 2026-08-15)

Вертикальное видео, загруженное обычным флоу
(`video.save(group_id=...)` → upload → `wall.post`), **НЕ становится клипом**:

- Ролик 720×1280 (9:16), 3 сек загружен в тестовую группу `96798355`
  и опубликован на стену (пост **8140**, видео **456239211**).
- В посте вложение имеет `"type": "video"` — обычное видео, не клип.
- `video.get` по этому видео не возвращает **ни одного** поля-признака клипа
  (`is_clip`, `short_video` и т.п.): `type=video`, `width=720`, `height=1280`, `duration=3`.
- Раздел «Клипы» сообщества (`vk.com/clips-96798355`): **«У автора пока нет клипов»**.

Отдельный API-метод `shortVideo.create` **существует** (им пользуются с 2020 года,
см. форумы), но с нашими токенами **недоступен**:

| Токен | Результат |
|---|---|
| user-токен (vkhost, приложение VFeed 4083558) | error 3 «Unknown method passed» |
| ключ сообщества (`VK_GROUP_TOKEN`) | error 3 «Unknown method passed» |
| Все версии API (5.101 / 5.123 / 5.126 / 5.131 / 5.132 / 5.154 / 5.199 / 5.249) | error 3 «Unknown method passed» |

По данным сообщества (lolz.team, v-h.guru, ru.stackoverflow) метод работает
только с токенами от **определённых приложений** (рекомендация — «токен берите
у vkhost, кнопка vk.com», т.е. официальное приложение ВК). В dev.vk.com метод
**не документирован**. Для рабочего скрипта это ненадёжно.

**Вывод: через API клипы загрузить нельзя.** Гарантированный способ — только
через приложение ВК или веб-интерфейс (вручную или UI-автоматизацией).

Требования клипов ВК: вертикаль **9:16** (1080×1920), длина **3 сек – 3 мин**,
до **1 ГБ**, Full HD 60 FPS.

## Предложение: автоматизация загрузки клипов через Playwright

Раз API закрыт, клип можно загрузить через веб-интерфейс `vk.com` с помощью
Playwright: браузер повторяет действия человека в разделе «Клипы».

- **Плюсы**: не зависит от API и токенов; принимает всё, что принимает веб-форма.
- **Минусы**: хрупко к изменениям вёрстки, CAPTCHA/2FA, риск ограничений при
  частых загрузках, нужна живая сессия (cookies).

### Шаг 0. Установка

```bash
pip install playwright
playwright install chromium
```

### Шаг 1. Как получить cookies (живая сессия)

Надёжный способ — `storage_state` Playwright (хранит cookies **и** localStorage,
что важно для VK):

1. Один раз запустите браузер **в видимом окне** и войдите в ВК вручную
   (логин + 2FA/CAPTCHA может сделать только человек):

```python
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch(headless=False)  # видимое окно
    ctx = browser.new_context()
    page = ctx.new_page()
    page.goto("https://vk.com/")
    input("Войдите в ВК в этом окне и нажмите Enter...")
    ctx.storage_state(path="vk_state.json")   # сессия сохранена
    browser.close()
```

2. Все дальнейшие запуски — headless, с подгрузкой сессии:

```python
ctx = browser.new_context(storage_state="vk_state.json")
```

Альтернатива: экспорт cookies расширением EditThisCookie, но `storage_state`
надёжнее.

> **Безопасность**: `vk_state.json` = живой доступ к аккаунту. Храните только
> локально, добавьте в `.gitignore`, не коммитьте и не передавайте никому.
> Сессия протухает — периодически обновляйте.

### Шаг 2. Как найти селекторы (исследовать код страницы)

Не гадайте — исследуйте. Два рабочих способа:

**A. Playwright Codegen (быстрее всего):**

```bash
playwright codegen https://vk.com/clips-96798355
```

Откроется браузер + инспектор. Каждое ваше действие записывается в код
с селекторами: кликните «Опубликовать», выберите файл, нажмите публикацию —
и скопируйте готовые селекторы.

**B. DevTools вручную:**

1. Откройте `vk.com/clips-<id>` → F12 → вкладка Elements.
2. Наведите курсор на кнопку «Опубликовать», поле описания, `input[type=file]` —
   увидите тег, `id`, `data-testid`, классы.
3. Проверьте уникальность селектора в консоли:
   `document.querySelectorAll('ваш-селектор').length` должно быть `1`.

Приоритет надёжности селекторов:
1. Роль/текст: `get_by_role("button", name="Опубликовать")`, `get_by_text(...)`;
2. `data-testid` / стабильные `id`;
3. CSS-классы — **в последнюю очередь** (VK часто их меняет).

Особенность VK: `input[type=file]` скрытый — Playwright умеет
`set_input_files` по нему, даже когда он невидим.

### Шаг 3. Каркас скрипта (предложение, в репо не реализовано)

```python
from playwright.sync_api import sync_playwright

GROUP_ID = "96798355"
VIDEO = "clip.mp4"  # вертикальный MP4 9:16, 3 сек–3 мин, ≤1 ГБ

with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)
    ctx = browser.new_context(storage_state="vk_state.json")  # шаг 1
    page = ctx.new_page()
    page.goto(f"https://vk.com/clips-{GROUP_ID}", wait_until="networkidle")

    # 1. Кнопка «Опубликовать» на странице клипов сообщества
    page.get_by_text("Опубликовать", exact=True).first.click()

    # 2. Скрытый input[type=file] в модалке загрузки
    page.locator("input[type=file]").set_input_files(VIDEO)

    # 3. Дождаться обработки файла (подберите реальный селектор превью/описания)
    page.wait_for_timeout(15000)

    # 4. Описание (хештеги)
    desc = page.get_by_placeholder("Добавьте описание").first
    if desc.is_visible():
        desc.fill("Клип #тест")

    # 5. Публикация
    page.get_by_text("Опубликовать", exact=True).last.click()

    page.wait_for_timeout(3000)
    print("Готово. Проверьте vk.com/clips-96798355")
    browser.close()
```

Это **каркас**: селекторы и тайминги определяйте на шаге 2 под текущую вёрстку.

### Шаг 4. Подводные камни

- **CAPTCHA / 2FA**: при подозрении ВК попросит подтверждение — headless падает.
  Лечение: реже загружать, имитировать человека (паузы, курсор), при
  необходимости ручное подтверждение в headed-режиме.
- **Детект headless**: `headless=False` + реальный user-agent; при массовых
  загрузках — прокси и разные сессии.
- **Протухание сессии**: перед загрузкой проверяйте, что открыта страница
  клипов, а не форма логина.
- **Изменение вёрстки**: VK меняет классы/структуру — перепроверяйте селекторы,
  не закладывайтесь на классы без проверки.
- **Частые загрузки** → риск ограничений/бана; соблюдайте паузы.
- **Локализация**: текст кнопок зависит от языка интерфейса — предпочитайте
  `data-testid` текстовым селекторам.
