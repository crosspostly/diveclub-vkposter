# Установка и запуск: отложенный постинг видео в ВК от имени сообщества

Инструкция для тех, кто хочет запустить этот скрипт у себя.
Полный проход занимает ~10 минут: файлы → токены → запуск.

---

## 1. Что нужно передать / получить

**Скрипту нужны только эти файлы** (всё остальное — служебное):

| Файл | Зачем |
|---|---|
| `post.py` | CLI: принимает текст, `--video`, `--at`, читает `.env` |
| `vk_poster.py` | Логика VK API: загрузка видео/фото, `wall.post` |
| `requirements.txt` | Зависимости: `aiohttp`, `python-dotenv` |
| `.env.example` | Шаблон конфига (скопировать в `.env` и вписать свои токены) |

Проще всего: **скинуть весь репозиторий** — архивом папки или
[скачать zip с GitHub](https://github.com/crosspostly/diveclub-vkposter) (зелёная кнопка
`<> Code` → `Download ZIP`). Внутри уже есть всё, включая `README.md` и этот файл.

> ⚠️ Файла `.env` в репозитории нет и быть не должно — в нём лежат твои токены.
> Если кто-то прислал тебе `.env` — это утечка секретов, попроси перевыпустить токены.

---

## 2. Предварительные требования

- **Python 3.10+** (проверка: `python --version`; если нет — python.org)
- Аккаунт ВК — **администратор** сообщества, куда будут поститься видео
- Само сообщество с включённым доступом к API (Управление → Настройки → Работа с API → «Включено»)

---

## 3. Установка

В папке с файлами скрипта:

```bash
# Windows (PowerShell)
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt

# macOS / Linux
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
```

---

## 4. Получение токенов (самый важный шаг)

Скрипту нужны **два разных токена**. Это принципиально: ВК принимает загрузку медиа
(фото и видео) **только с пользовательского токена**, а публикацию поста делает ключ
сообщества.

### 4.1. Ключ сообщества — `VK_GROUP_TOKEN`

1. ВК → своё сообщество → **Управление → Настройки → Работа с API**
2. Вкладка **«Ключи доступа»** → «Создать ключ»
3. Отметить права: **`wall`, `photos`, `groups`, `offline`**
4. Скопировать ключ (начинается с `vk1.a.`)

### 4.2. User-токен — `VK_USER_TOKEN`

Это токен **личного аккаунта** (того, кто админ сообщества). Медиа ВК можно грузить
только им. Есть два способа получить — простой и запасной.

#### Вариант А (проще): через vkhost.github.io — приложение VFeed

1. Открой **https://vkhost.github.io** (агрегатор готовых OAuth-ссылок; сам токен
   выдаёт ВК, а не сайт — передавать его никому нельзя)
2. В списке приложений найди **VFeed** (приложение для iPhone,
   ID приложения: **4083558**)
3. Нажми кнопку **VFeed** напротив него
4. ВК спросит разрешение — нажми **«Разрешить»** (выдать доступ)
5. Произойдёт переход на `https://oauth.vk.com/blank.html#access_token=...`
6. Скопируй из адресной строки всё между `access_token=` и `&` — это и есть токен

#### Вариант Б (запасной): через своё Standalone-приложение

1. Создать приложение: https://vk.com/apps?act=manage → «Создать приложение» →
   тип **«Standalone»** → записать его числовой **`ID`**
2. Открыть ссылку (подставь `APP_ID`):

   ```
   https://oauth.vk.com/authorize?client_id=APP_ID&display=page&redirect_uri=https://oauth.vk.com/blank.html&scope=photos,video,offline&response_type=token&v=5.199
   ```

3. Разрешить доступ → произойдёт переход на `oauth.vk.com/blank.html#access_token=...`
4. Скопировать из адресной строки всё после `access_token=` (до `&`) — это и есть токен

> Токен бессрочный, пока не отозван (право `offline`). Никому его не передавай —
> с ним можно постить от твоего имени. Оба варианта дают одинаковый токен:
> приложение может быть любым, главное — права `photos`, `video`, `offline`.

### 4.3. ID сообщества — `VK_GROUP_ID`

Числовой ID (например `96798355`), без минуса. Есть в адресе группы
(`vk.com/club96798355`) или в настройках сообщества.

---

## 5. Настройка `.env`

```bash
# Windows (PowerShell)
Copy-Item .env.example .env

# macOS / Linux
cp .env.example .env
```

Открыть `.env` и вписать:

```ini
VK_GROUP_TOKEN=vk1.a.ВАШ_КЛЮЧ_СООБЩЕСТВА...
VK_GROUP_ID=123456789
VK_USER_TOKEN=vk1.a.ВАШ_USER_ТОКЕН...
VK_API_VERSION=5.199
DRY_RUN=false
```

---

## 6. Проверка без публикации (рекомендуется)

```bash
# Windows
$env:DRY_RUN="true"; .venv\Scripts\python post.py "тест"

# macOS / Linux
DRY_RUN=true .venv/bin/python post.py "тест"
```

Должен появиться лог `DRY_RUN wall.post: ...` — реального поста не будет.

---

## 7. Запуск

```bash
# Сразу опубликовать с видео
.venv\Scripts\python post.py "Текст поста" --video clip.mp4

# Отложенно (ISO 8601 с часовым поясом; минимум ~5 минут в будущее)
.venv\Scripts\python post.py "Текст поста" --video clip.mp4 --at 2026-08-16T09:00:00+03:00

# Несколько файлов: до 10 медиа суммарно (фото + видео)
.venv\Scripts\python post.py "Текст" --photo 1.jpg --photo 2.jpg --video clip.mp4
```

Успех: `OK: post_id=...` в логе, пост на стене от имени сообщества.
Видео попадает в **видеотеку сообщества** и **не появляется в видеотеке автора**.
Проверить пост можно открыв стену сообщества (скрипт читать стену ключом сообщества
не может — это ограничение ВК, читай только через сайт или user-токеном).

---

## 8. Ограничения и частые ошибки

| Ситуация | Что делать |
|---|---|
| Видео до 2 ГБ; форматы AVI/MP4/3GP/MPEG/MOV/MP3/FLV/WMV | Конвертни в MP4, если файл не грузится |
| `error 5 User authorization failed` на видео | `VK_USER_TOKEN` не задан/неверный или нет права `video` |
| `error 27 Group authorization failed` на фото | Медиа-загрузка только user-токеном, ключ сообщества не подходит |
| `--at` в прошлом или слишком близко | ВК отклоняет или публикует сразу; ставь ≥ 5 минут вперёд |
| Видео после загрузки «обрабатывается» | ВК конвертирует в фоне; в посте может быть заглушка несколько минут |
| `error 214` на видео | Нет прав на запись в сообществе (нужен админ) |
| `error 219` | Слишком частый рекламный пост — подожди |

---

## 9. Если что-то пошло не так

- Проверь, что `.env` на месте и токены полные (от `vk1.a.` до конца)
- Прогони `DRY_RUN` (шаг 6) — он показывает, что скрипт вообще доходит до публикации
- Пост ушёл, но видео не видно? Подожди 5–10 минут: ВК обрабатывает видео в фоне
- Для живой отладки: `python -c "import post"` не нужно — просто запусти `post.py`
  и читай лог, он пишет `OK:` / `FAILED:` и причину
