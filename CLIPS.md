# VK Клипы (Clips): загрузка видео в ВК — разнесение путей

## Сводная таблица: куда какое видео и как загружать

Проверено живыми тестами (2026-08-15/16, аккаунт 11813721 «Павел Шехов»,
группы 96798355 «! тест» и 92478300):

| Куда | Горизонтальное видео | Вертикальное видео (клип) |
|---|---|---|
| **Страница пользователя** | `video.save` (без `group_id`) + `wall.post` — обычный API, **бубен не нужен**, токена достаточно | ТО ЖЕ САМОЕ: `video.save` (без `group_id`) + `wall.post` — ВК сам делает клип (`type: short_video`). Проверено: пост 4916, видео 456240323 (3:4) |
| **Сообщество** | `video.save(group_id=...)` + `wall.post` — обычный API, user-токен. Проверено: посты 8140–8142, видео 456239211–213 | **Только** `shortVideo.create` (закрытый метод) + токен официального приложения. `video.save` + `wall.post` клип в сообществе НЕ создаёт (все форматы → `type: video`) |

**Вывод: решает адресат, а не формат.**
- на страницу пользователя — **бубен не нужен**, токена достаточно;
- в группу горизонталь — **по API**;
- в группу вертикаль (клип) — **с бубеном** (`shortVideo.create`).

## Коротко

Клип **в сообщество** загружается закрытым методом `shortVideo.create`
(его нет в dev.vk.com). Метод принимает **только токены официального
приложения ВК** — и их два способа получить:

1. **VK_CLIP_TOKEN** — vkhost.github.io → кнопка «vk.com» (проверено:
   метод существует, но живого теста с таким токеном не было).
2. **Web-токен из живой браузерной сессии** (✅ **единственный живой путь**):
   перехват ответа `POST login.vk.ru/?act=web_token`
   (`version=1&app_id=6287487&access_token=<webToken>`) — SPA vk.ru сама
   дёргает этот эндпоинт при загрузке авторизованной страницы и получает
   `{"type":"okay","data":{"access_token":"...","user_id":...,...}}`.
   **Токен 220 символов, короткоживущий (~5–10 мин, затем error 5) — брать
   перед каждым вызовом.** В HTML/DOM SPA токен НЕ встраивается
   (опровергнуто диагностикой). Нужен **редактор/админ группы**, иначе
   error 15 «Access denied».

С обычными токенами (VFeed и т.п.) и ключом сообщества метод не работает —
error 3 «Unknown method passed».

Рабочий скрипт на web-токене — **`clip_web_upload.py`** (куки браузера,
без `VK_CLIP_TOKEN`); альтернатива с токеном vk.com — **`clip_upload.py`**.

## Как это работает: `shortVideo.create`

Запрос: `POST api.vk.com/method/shortVideo.create` с параметрами:

| Параметр | Значение |
|---|---|
| `access_token` | **токен официального приложения** (vkhost «vk.com») |
| `group_id` | id сообщества (клип попадёт в раздел «Клипы» сообщества) |
| `wallpost` | `1` — сразу на стену, `0` — только в клипы |
| `description` | описание клипа (хештеги) |
| `file_size` | размер файла в байтах |
| `v` | 5.132–5.249 (можно 5.199) |

Ответ: `{owner_id, video_id, upload_url}`. Затем `POST` на `upload_url`:
multipart-поле **`file`**, user-agent **`vk-test-clip-upload 1`**.
Успех = HTTP 200 + тело `<retval>1</retval>`.

**Токен**: `vkhost.github.io` → кнопка **«vk.com»** (официальное приложение ВК).
Токен в `.env` → `VK_CLIP_TOKEN=<токен>` (в `.gitignore`, не коммитить).

**Ролик**: MP4, H.264, вертикаль 9:16 (1080×1920), 3 сек – 3 мин, ≤ 1 ГБ.
(В группе 92478300 все клипы именно 9:16 1080×1920 — 3:4 через
`shortVideo.create` не проверено.)

**Запуск**:
```bash
.venv/bin/python clip_upload.py clip.mp4 "Описание #хештег"        # wallpost=1
.venv/bin/python clip_upload.py clip.mp4 "" --wallpost 0           # только клип
```

Если токена vk.com нет — фолбэк: загрузка через веб-интерфейс (Playwright, ниже).

## ⚠️ Актуальный статус (2026-08-16, после UI-диагностики)

**Коротко: объект клипа через `shortVideo.create` создаётся и загружается,
НО появление в разделе «Клипы» (`shortVideo.getOwnerVideos`) пока НЕ
доказано.** Ниже — полная правда по результатам живых экспериментов.

### Реальный веб-флоу (перехвачен в UI, v=5.285, api.vk.ru)

Современная SPA публикует клип так (всё через `api.vk.ru/method/*`
с `v=5.285&client_id=6287487`, токен = webToken):

1. `shortVideo.getGroupsForUploading` — список групп, куда можно загружать
   (возвращает `current_user` + `groups[]` с `admin_level`).
2. `shortVideo.create` с `file_size=<байты>&group_id=<gid>`
   → `{owner_id: -96798355, video_id: 4562392xx, upload_url: https://ovu.mycdn.me/upload.do?...}`.
3. `POST` на `upload_url` (multipart `file`) → `{video_hash, size, owner_id, video_id}`.
4. Поллинг `shortVideo.encodeProgress` (`video_id&owner_id&hash`) до
   `percents: 100, is_ready: true` — ВК перекодирует в фоне.
5. UI показывает страницу «Публикация клипа»: «Клип загружен и обработан»,
   поле «Описание», обложка (3 кадра), кнопка «Опубликовать»
   (`button[data-testid="clips-publish-button"]`, может быть ниже скролла).

### `shortVideo.publish` — пока НЕ работает (error 100)

Попытка вызвать `shortVideo.publish` напрямую (webToken, api.vk.ru/vk.com,
v=5.131–5.285, с/без client_id, с hash, `license_agreement` = 1/"true"/True/0/
отсутствует, в query/body) → **всегда error 100
«One of the parameters specified was missing or invalid: 4: license_agreement
must by true»**. Точный формат параметра неизвестен; правильный запрос виден
только при реальном клике «Опубликовать» в UI (см. раздел Playwright ниже).

### ВАЖНО про видимость

- Клипы НЕ показываются в `video.get` (видеотека — только `type: video`),
  но `video.get` по прямому id (`videos=-<gid>_<vid>`) отдаёт клип
  (`type: short_video`, пустой title, `repeat: 1`, `is_united_video: 1`).
- Клипы НЕ попадают на стену (ни `wallpost=1`, ни `wall.post` с вложением).
- Эталон: группа 92478300 — 170 роликов 9:16, часть `type: short_video`
  (456239326/323/322/321) — они в разделе «Клипы» есть, т.е. механизм
  существует; как именно они туда попали — исходно неизвестно (старый
  клиент/флоу).

### Скрипты

- **`clip_web_upload.py`** — `shortVideo.create` + web-токен из кук.
  Создаёт объект клипа (owner_id отрицательный), но раздел «Клипы»
  (`getOwnerVideos`) он не наполняет — нужен финальный publish-шаг
  (см. раздел Playwright). **Не считать «доказанным путём в раздел».**
- `clip_upload.py` (VK_CLIP_TOKEN от vkhost «vk.com») — живой тест не
  проводился.

## Фолбэк: автоматизация загрузки клипов через Playwright

Если токена vk.com нет, клип можно загрузить через веб-интерфейс `vk.com`
с помощью Playwright: браузер повторяет действия человека в разделе «Клипы».

- **Плюсы**: не зависит от API и токенов; принимает всё, что принимает веб-форма.
- **Минусы**: хрупко к изменениям вёрстки, CAPTCHA/2FA, риск ограничений при
  частых загрузках, нужна живая сессия (cookies).

### Шаг 0. Установка

```bash
pip install playwright
playwright install chromium
```

### Шаг 1. Как получить cookies (живая сессия)

Надёжный способ — `storage_state` Playwright (хранит cookies **и** localStorage,
что важно для VK):

1. Один раз запустите браузер **в видимом окне** и войдите в ВК вручную
   (логин + 2FA/CAPTCHA может сделать только человек):

```python
from playwright.sync_api import sync_playwright

with sync_playwright() as p:
    browser = p.chromium.launch(headless=False)  # видимое окно
    ctx = browser.new_context()
    page = ctx.new_page()
    page.goto("https://vk.com/")
    input("Войдите в ВК в этом окне и нажмите Enter...")
    ctx.storage_state(path="vk_state.json")   # сессия сохранена
    browser.close()
```

2. Все дальнейшие запуски — headless, с подгрузкой сессии:

```python
ctx = browser.new_context(storage_state="vk_state.json")
```

Альтернатива: экспорт cookies расширением EditThisCookie, но `storage_state`
надёжнее.

> **Безопасность**: `vk_state.json` = живой доступ к аккаунту. Храните только
> локально, добавьте в `.gitignore`, не коммитьте и не передавайте никому.
> Сессия протухает — периодически обновляйте.

### Шаг 2. Как найти селекторы (исследовать код страницы)

Не гадайте — исследуйте. Два рабочих способа:

**A. Playwright Codegen (быстрее всего):**

```bash
playwright codegen https://vk.com/clips-96798355
```

Откроется браузер + инспектор. Каждое ваше действие записывается в код
с селекторами: кликните «Опубликовать», выберите файл, нажмите публикацию —
и скопируйте готовые селекторы.

**B. DevTools вручную:**

1. Откройте `vk.com/clips-<id>` → F12 → вкладка Elements.
2. Наведите курсор на кнопку «Опубликовать», поле описания, `input[type=file]` —
   увидите тег, `id`, `data-testid`, классы.
3. Проверьте уникальность селектора в консоли:
   `document.querySelectorAll('ваш-селектор').length` должно быть `1`.

Приоритет надёжности селекторов:
1. Роль/текст: `get_by_role("button", name="Опубликовать")`, `get_by_text(...)`;
2. `data-testid` / стабильные `id`;
3. CSS-классы — **в последнюю очередь** (VK часто их меняет).

Особенность VK: `input[type=file]` скрытый — Playwright умеет
`set_input_files` по нему, даже когда он невидим.

### Шаг 3. Реальный рабочий флоу (проверен 2026-08-16, pw_ui_full*.py)

Проверенный на живом аккаунте сценарий (persistent-профиль Playwright +
перехват сети) — это **самый близкий к успеху путь**:

1. Открыть `https://vk.ru/clips/upload-96798355` в авторизованном профиле
   (persistent context, channel `msedge`, `headless=False`).
2. Кликнуть кнопку `button[data-testid="clips-publish-button"]` (текст
   «Опубликовать») — **открывает модалку «Новый клип»** и вызывает
   `shortVideo.getGroupsForUploading`.
3. Найти `input[type=file]` (в модалке, может быть во фрейме) и
   `set_input_files(clip.mp4)` **напрямую** — не кликать «Выбрать файл»
   (в v1 клик промахнулся).
4. SPA сама дёргает `shortVideo.create` → `upload_url` (ovu.mycdn.me) →
   POST файла → поллинг `shortVideo.encodeProgress` до `is_ready: true`.
5. UI переходит на страницу «Публикация клипа»: «Клип загружен и обработан»,
   поле «Описание» (`placeholder "О чём ваш клип?"`), обложка (3 кадра),
   переключатели «Разрешить комментарии/дуэты». Кнопка «Опубликовать» —
   `button[data-testid="clips-publish-button"]`, может быть **ниже скролла**.
6. **Дождаться `is_ready=true` и ТОЛЬКО ПОТОМ кликать «Опубликовать»** —
   в v2/v3 клик до готовности не дал publish-запроса (модалка закрылась).
   Публикация-запрос при этом пока не перехвачен — это открытый вопрос
   (см. «Актуальный статус» выше).

Перехват webToken: слушать `response` на `login.vk.ru/?act=web_token`,
токен лежит в JSON-теле (`data.access_token`). Он **короткоживущий** —
добывать в той же сессии, что и вызовы API.

### Шаг 4. Подводные камни

- **CAPTCHA / 2FA**: при подозрении ВК попросит подтверждение — headless падает.
  Лечение: реже загружать, имитировать человека (паузы, курсор), при
  необходимости ручное подтверждение в headed-режиме.
- **Детект headless**: `headless=False` + реальный user-agent; при массовых
  загрузках — прокси и разные сессии.
- **Протухание сессии**: перед загрузкой проверяйте, что открыта страница
  клипов, а не форма логина.
- **Изменение вёрстки**: VK меняет классы/структуру — перепроверяйте селекторы,
  не закладывайтесь на классы без проверки.
- **Частые загрузки** → риск ограничений/бана; соблюдайте паузы.
- **Локализация**: текст кнопок зависит от языка интерфейса — предпочитайте
  `data-testid` текстовым селекторам.
